## 构建位置

所有涉及编译、交叉编译和构建的工作，默认统一交给远端编译服务器完成，包括 Linux 内核、内核模块、设备树和覆盖层（DTB/DTBO）、U-Boot、ATF 等。树莓派和 RK3588 负责源码编辑、任务控制、取回、校验、部署和运行调试。远端失败时不要自动改为树莓派或 RK3588 本地编译；用户明确要求本地构建时，按用户指令执行。

远端计算应尽量利用可用性能，但必须遵守资源边界。每次任务先实际检查 SSH 认证、远端架构、目标架构、CPU、`nproc`、内存、磁盘空间、当前负载和可用 toolchain。RK3588 目标为 arm64；若服务器是 x86，应使用匹配的 arm64 交叉编译器，不能把 x86 产物当作 ARM 产物。并行度依据远端 `nproc` 和内存决定：资源充足时按可分配 CPU 使用 `make`/`ninja` 并行；出现 OOM 或明确资源限制时，根据证据降低并行度。避免硬编码 `-j1`、`-j2` 和无限并行；多个任务同时运行时保持合理总并发，不影响他人作业。

已知控制入口：Mac 可执行 `ssh rpi4b-aliyun`，树莓派可执行 `ssh rk3588-usb`。用户已确认默认远端编译服务器为 `10.191.32.121`，SSH 端口为 `22`，树莓派到该端口的网络连通性已验证。实际构建前使用已授权的服务器账号和认证方式完成 SSH 登录检查，确认登录成功后再启动远端构建。RK USB 地址为 `169.254.4.1`，树莓派为 `169.254.4.2`。

## 隔离与记录

远端构建使用任务专用目录，不能删除或覆盖他人文件。开始前记录源码提交、分支、未提交改动、配置文件、目标板和 toolchain；存在未提交改动时先保留并明确记录。构建日志必须保存真实命令和退出码，不得用后续命令掩盖失败。

取回内容限定为任务所需产物及校验资料。每次构建同时生成 `SHA256SUMS` 或 manifest，至少记录源码提交、配置哈希、toolchain、构建命令、目标板和产物 SHA-256。取回前检查树莓派可用空间，取回后先校验，再进入部署流程。

## 部署与刷写

构建授权不等于当前烧录授权。只按用户当前明确范围部署或刷写；涉及真实设备时，先核对板卡、启动介质、分区、备份和恢复路径，保留可回滚资料。不得依据通用偏移猜测写盘位置，也不得把准备好的镜像视为已经刷写成功。完成状态必须以实际设备检查为准，不新增无关的重复确认流程。

不得把 Codex auth、SSH 私钥、账户密码或其他秘密传到编译机，也不得写入本文件、构建日志、manifest 或产物说明。任务仅需编译时，不扩大到刷写、重启、模式切换或其他设备状态变更。
