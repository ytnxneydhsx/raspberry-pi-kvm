# 远端 x86-64 编译命令

## 目标

树莓派通过 `x86-build` 把本地源码临时传到 x86-64 服务器，在远端执行 GCC、G++、Make、CMake 或其他构建命令，取回指定产物，再删除远端临时工作区。

```text
树莓派源码
    ↓ rsync + SSH
/tmp/x86-build-<唯一编号>/src
    ↓ x86-64 构建命令
指定产物
    ↓ tar + SSH
树莓派原目录
    ↓
删除远端临时工作区
```

## 当前环境

- 树莓派：Debian 13，ARM64。
- 远端：`10.191.32.121`，x86-64。
- SSH 身份：树莓派使用独立 ED25519 密钥以 `fx` 用户连接。
- 远端工具：GCC、G++、Make、CMake、Ninja、pkg-config、rsync、tar 和 Python 3。

SSH 私钥只保存在树莓派的 `~/.ssh/`，不进入仓库。`x86-build` 配置中只保存 SSH 主机和远端临时根目录。

## 初始化

```bash
x86-build init --host 10.191.32.121
x86-build doctor
```

## 使用

```bash
x86-build run \
  --source <源码目录> \
  --output <需要取回的相对路径> \
  -- <远端执行的命令>
```

例如，远端编译一个 x86-64 C 程序：

```bash
x86-build run \
  --source ~/hello \
  --output hello \
  -- gcc -O2 -Wall hello.c -o hello
```

例如，使用 Rockchip x86-64 `boot_merger` 生成 RK3588 loader：

```bash
x86-build run \
  --source ~/rk3588-official/rkbin \
  --output rk3588_loader_v1.24.114.bin \
  -- ./tools/boot_merger RKBOOT/RK3588MINIALL.ini
```

`boot_merger` 在 x86-64 服务器上运行，输出的 loader 内部仍然是 RK3588 使用的 DDR、usbplug 和 SPL 固件。

## 失败与清理

正常成功、构建失败和本地中断都会进入远端清理流程。如果网络中断导致清理请求未到达，连接恢复后执行：

```bash
x86-build gc
```

该命令默认只删除超过 24 小时、同时带有 `.x86-build-managed` 标记的 `/tmp/x86-build-*` 目录。
