# 第一阶段计划

- 整理日期：2026-10-17。
- 依据：用户已确认的产品需求与本轮范围讨论。
- 完整产品需求见 [开发板调试网关产品需求](开发板调试网关产品需求.md)。
- 本文记录当前交付目标、后续应用范围和实施顺序，不代表已经执行构建、烧录或板端验收。

## 1. 当前方向

先完成可独立使用的 RK3588 底层构建、烧录和板端生效闭环，再向上搭建后台任务服务与网页。

以连续交付节点组织工作，不将网页完成作为底层能力交付的前提。网页后续复用底层执行能力。

```text
确认板卡、源码与烧录资料
    ↓
命令行远端构建指定组件
    ↓
取回产物并保留构建记录
    ↓
人工将板子准备到可烧录状态
    ↓
树莓派通过底层执行入口完成烧录
    ↓
人工配合重启，确认板端生效
    ↓
补齐整机烧录、软件切换模式及执行管理
    ↓
后台接口与网页应用
```

## 2. 已确认的范围决策

| 项目 | 决策 |
|---|---|
| 当前交付重点 | 先实现底层烧录闭环，之后搭建网页 |
| 专用板卡适配 | 当前只做 RK3588 的烧录适配 |
| 使用方式 | 单管理员，一次操作一块板子 |
| 烧录范围 | 同时覆盖整套系统与单独组件／分区，具体流程由板卡适配定义 |
| 最早跑通方式 | 人工准备到可烧录状态，再由底层程序执行 |
| 软件切换模式 | 后续补入底层能力，系统正常时尝试通过预设 SSH 命令切换；失败时提示人工处理 |
| 源码构建定位 | 开发准备，通过命令行完成；网页不承担源码构建管理 |
| 源码构建范围 | 指定组件，例如内核与设备树；具体目标随可用源码确定 |
| 生效确认 | 属于研发验收，确认新系统能启动或新组件实际生效 |
| 镜像管理 | 文件保留在网关，后续可命名、查看说明、复用和删除 |
| 烧录方案维护 | 随板卡适配准备；网页选择已有方案，不提供通用方案编辑器 |
| 镜像适配检查 | 不做镜像与板卡的兼容性检查或相关前置拦截 |
| 失败处理 | 停止并保留失败阶段、日志和结果，由操作者决定后续处理 |
| 容量目标 | 暂不量化人数、板数或并发上限，不安排容量验证或压测 |

整机烧录能力与组件源码构建分别保留：指定组件由本次开发准备流程生成，整套系统镜像允许从外部导入。

## 3. 源码构建作为开发准备

沿用项目现有构建规则，默认将编译交给远端构建服务器，树莓派负责控制、取回产物和烧录。具体约束见 [树莓派构建规则](../ops/raspberry-pi-codex-AGENTS.md)。

- 根据查明的板型、源码和构建配置选择首个组件目标。
- 记录源码版本、配置、工具链、构建命令、日志和结果。
- 生成所需产物及可追溯资料，并按现有规则取回、校验。
- 不将网页源码选择、远端编译按钮或构建配置编辑器列入当前网页范围。
- 当前不要求自行构建完整系统镜像。

这里的产物记录与传输校验服务于构建追溯，不扩展为产品中的镜像兼容性检查。

## 4. 底层烧录能力

### 4.1 可复用执行入口

复用 Rockchip 现有工具，封装与当前 RK3588 板卡对应的执行方案，形成可以通过命令行调用、随后供后台服务复用的入口。

底层入口负责：

- 定位当前目标设备并展示实际连接或模式状态。
- 选择板卡适配中已有的烧录方案及输入文件。
- 执行整套系统或组件／分区写入。
- 记录执行命令、阶段、输出、退出结果和失败信息。
- 约束同一目标板子的重复操作，保留整板资源锁的模型。
- 将执行能力与网页展示分开。

具体命令、镜像格式、loader、分区和地址来自查明的板卡方案，尚未确定的参数保持开放。

### 4.2 先跑通人工准备路径

首个底层闭环从已经由人工准备到可烧录状态的设备开始，先完成组件写入与生效确认。

随后补入预设 SSH 命令辅助切换模式。系统或通道不可用、切换失败时，显示状态并提示人工处理。

### 4.3 执行记录与任务承接

底层持续保留日志与结果，为后续任务状态查询提供依据。后台任务服务承接后，已启动的烧录独立于网页连接运行，网页关闭或网络断开不终止烧录。

失败后停止并保留记录，不自动重试。任务执行期间占用当前板子。

## 5. 研发验收标准

首个闭环以板端生效为完成标准：

1. 从已确定的源码和配置构建出指定组件。
2. 将对应产物取回并执行烧录，保留过程记录。
3. 根据需要人工配合重启板子。
4. 通过对应的启动日志、版本或其他直接证据，确认系统能启动或新组件实际生效。

具体生效证据随组件目标确定。例如更新内核时，可结合启动日志和运行中的内核信息确认。

研发阶段的生效确认与后续网页结果展示分别处理：网页范围以工具执行状态、进度和结果为主，自动启动验证暂不纳入。

## 6. 后续网页应用范围

在底层能力跑通后，网页专注 RK3588 烧录：

- 单管理员登录。
- 当前目标设备的连接、模式和占用状态。
- 镜像上传、列表、命名、说明、选择和删除。
- 选择预置的整机或组件／分区烧录方案。
- 通过已配置命令辅助切入烧录模式。
- 发起任务、查看进度、日志和结果。
- 重新连接后查看仍在运行的任务与历史记录。
- 现场网线直连、局域网和异地远程访问。

网页建立在相同的底层执行与记录能力上，后台接口的具体形式后续设计。

## 7. 本轮延后的完整产品能力

下列能力保留在完整产品需求中，当前围绕 RK3588 烧录的交付不展开：

- 多成员准入、协作观看、控制权申请队列与交接。
- 多板同时操作与并行烧录。
- 通用板卡调试页面及多板会话管理。
- 网页交互式串口和 SSH 终端。
- 板内完整文件管理、在线文本编辑与版本历史。
- 网页自动确认烧录后系统启动或组件生效。

镜像文件管理仍属于烧录工具范围，与板内完整文件管理分别处理。

不加入配套电源、硬件复位、多接头硬件、自定义任务流程、网页外通知或专门的网关备份恢复功能。

## 8. 实施节点与各自交付物

| 节点 | 工作 | 交付物 |
|---|---|---|
| 1. 资料与方案 | 查明板卡、存储、源码、构建配置、loader 和分区方案 | 可追溯的板卡资料与待执行方案 |
| 2. 组件构建 | 在远端构建指定组件，取回产物 | 构建命令、日志、配置、产物及追溯资料 |
| 3. 首个底层闭环 | 人工准备设备，命令行烧录组件，确认板端生效 | 可复用执行入口、烧录记录、生效证据 |
| 4. 补齐底层覆盖 | 整机与组件／分区方案、软件切换模式、执行与占用管理 | 供应用层复用的 RK3588 烧录能力 |
| 5. 后台与网页 | 镜像管理、任务查询、单管理员网页、本地和远程入口 | 专注烧录的网页应用 |

节点 3 是最早的实际可用交付点。后续网页进度不阻塞这一节点完成。

## 9. 待调查的事实

当前本地资料尚未明确以下信息，需要后续调查，不能作为已具备的条件：

- RK3588 的完整厂家型号和硬件修订版。
- 实际启动、写入介质及当前分区布局。
- SDK／内核源码位置、分支、配置与设备树。
- 对应 loader、整机镜像、组件格式和配套烧录方案。
- 可用的软件切换模式命令。
- 远端构建环境与当前认证、工具链状态。

已有工具安装和历史连接记录可作为调查线索，当前尚未以它们证明实际烧录链路已经走通。

后续开始具体构建、设备状态变更或烧录时，依据查明的板卡与文件明确实际执行范围。
