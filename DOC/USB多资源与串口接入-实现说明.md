# USB 多资源与串口接入

日期：2026-10-18。

## 目标与范围

在已有 VID/PID 发现模块后增加用户态设备能力层，先支持当前 RK3588 正常模式下的 USB 复合设备。一组 VID/PID 对应一个 USB 设备观察结果，下面可以有多个串口、网络和 USB interface 资源。复用 Linux 和 pySerial 的通用串口接口，保持设备发现、连接配置、实际操作的边界。

当前采用 `SerialChannel` 抽象基类约定配置、打开、关闭、读取、写入和状态查询，实际由 pySerial 适配实现。CH340、CH341 与 USB ACM 使用同一实现；当前不建立逐芯片继承树，不从驱动源码动态推导配置菜单。

## 业务过程

```text
Linux 设备资源
    → 已有采集器按 USB 父设备归并
    → VID/PID 匹配、保存发现历史、输出 RecognizedDevice
    → UsbDeviceAccess 保留多个资源
    → 用户选择一个串口资源与命名配置方案
    → SerialChannel.open() 应用参数
    → read()/write() 与调用方交换 bytes
    → 关闭或资源消失后断开，由用户手动连接
```

`key` 继续是 VID/PID 规则名称，不作为物理设备唯一身份或通信协议。按 `resources` 的具体子系统和入口选择能力。当前默认规则覆盖系统实际观察到的 `1d6b:0104` Gadget，该编号不专属于 RK3588，也不保证所有匹配设备的功能一致。

## 已确认的使用行为

- 串口配置项维护在 `code/device_access/serial_driver_options.json`，运行时按发现结果中的驱动名读取；未知驱动使用 `default`。用户选择具体值，候选项属于程序维护的配置说明，不宣称由 `.ko` 自动返回或代表实机完整支持清单。
- `tty`／`net` 子资源记录所属 USB 接口的驱动名，例如 `ttyACM0.driver = cdc_acm`、`ttyUSB0.driver = ch341`，供配置选择直接使用。
- 当前 RK3588 Linux USB Gadget 的 `cdc_acm` 只向用户提供读写超时；线路编码参数使用内部默认值，不作为 USB 传输速率选项。`ch341` 继续提供波特率等真实 UART 线路参数。
- 用户配置保存为命名方案，手动选择复用，不自动绑定板卡或端口。
- 构造对象与发现回调不自动连接；用户显式连接。
- 拔出关闭旧连接，重新接入不自动打开、不自动重发数据。
- 本模块不自动保存串口正文；完整产品的常驻日志能力仍保留为后续范围。
- USB 网络资源在设备对象内保留；当前不设置网络、执行 SSH 或烧录。

## 设计理由

Linux 与 pySerial 已经处理串口基本操作，薄适配层用于应用调用约定、独立连接状态和用户配置。相比每种芯片各写一套通信类，这样能够复用现有实现；新增代价是资源生命周期与配置方案存储需要维护。收益按“调用方能够明确选择资源、应用配置并获取结果”评估，不提前做容量承诺或压测。

`DeviceObservation` 仍是不可变观察快照；`UsbDeviceAccess` 组织当前可操作资源；`SerialChannel` 才管理打开后的连接。网络与烧录未来各自接入适合的操作接口。

## 实现与验证

源码位于 `code/device_access/`，公开入口、示例、异常和并发边界见 [模块说明](../code/device_access/README.md)。原发现模块的数据模型和历史链路不变。

已独立读取树莓派当前 USB/sysfs 和网络元数据，确认复合设备下存在 ACM 串口与 NCM 网卡。当前只进行静态检查，不以此宣称实际收发或拔插验收通过。实机 `open/read/write`、方案存储操作、事件接入和手动重连需后续得到明确验证指令后执行。
